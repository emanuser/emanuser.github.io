18 OCT 2026TESTING / BROWSER

When the test environment was the failure.

Our browser smoke test stopped at video loading. Instead of changing the application blindly, we checked decoder support: that headless Chromium build didn't support H.264. Swapping the synthetic fixture to VP8/WebM let us test the actual workflow.

OBSERVED RESULT Both JavaScript regressions and browser smoke checks passed; real-world detector accuracy remains unverified. Detailed CI logs are retained privately.

Sprocket's first assignment: find code, not excuses.

The first overly narrow repository search returned nothing. We widened the queries, kept the scope bounded, and retrieved four candidates in seventeen GitHub reads. A useful start—not proof any candidate is the right implementation.

003
18 OCT 2026OBSERVATION / VISION

A picture of a person isn't another person.

An object detector can mistake a printed figure or advertisement for someone physically present in a scene. Counting detections isn't the same as understanding the environment. Scene Context review makes it possible to flag and inspect those cases without pretending the model understood them.

LESSON Separate the observation from the conclusion—and keep the original detection evidence.

004
18 OCT 2026OBSERVATION / MEASUREMENT

The interesting action was inside the television.

When a phone records a screen, measuring changes across the entire camera frame can dilute what happens on the display. The next experiment is reviewer-selected Region of Interest analysis: measure the relevant pixels instead of everything around them.

Every good instrument has a measurement range. Every good evaluation has limitations.

Capture what the system actually did. No conclusions smuggled into measurements.

SECTION 04 / THE OPERATOR

Built by
Tom Dolgos.

A clean measurement and a correct conclusion are two different things.

My work spans image and caption grounding, robotics and first-person video QA, audio evaluation, adversarial benchmark design, and reviewer calibration. When an AI result is wrong, the useful question is why: model weakness, prompt ambiguity, annotation error, rubric conflict, or a flawed judge?

That perspective comes from more than two decades in industrial reliability, nondestructive testing, vibration analysis, repeatable data acquisition, technical procedures, and training. In both fields, an impressive-looking result is worthless if the measurement conditions cannot support it.
